# PROJECT TITAN-X -- Python dependencies

# INSTALL ORDER MATTERS ON A FRESH VENV. `pip install -r requirements.txt`
# in one pass FAILS with ResolutionImpossible, because pandas-ta 0.4.71b0
# publishes `numpy>=2.2.6` metadata while this project pins numpy<2 (see the
# pandas/numpy note below). On an existing environment pip tolerates it; on a
# brand-new venv the resolver treats that metadata as authoritative and
# refuses outright. Two passes:
#
#   1. python -m venv .venv                 # Python 3.12 ONLY -- see below
#   2. pip install -r <this file, minus the pandas-ta line> -e .
#   3. pip install pandas-ta==0.4.71b0 --no-deps
#
# `pip check` afterwards reports pandas-ta/numpy and pandas-ta/numba
# mismatches. Those are expected and informational -- pandas-ta runs fine
# against numpy<2 in practice.
#
# PYTHON 3.12, not whatever is newest. numpy 1.26.x has no prebuilt wheel for
# 3.13+, and building it from source needs GCC >= 8.4. Install with:
#   winget install --id Python.Python.3.12 --version 3.12.10 -e
#
# .venv IS NOT PORTABLE between machines -- pyvenv.cfg hardcodes an absolute
# interpreter path, so a copied .venv fails on every command with "No Python
# at ...". Always rebuild it after moving this folder.
